更新日期：2026-11-16。本文保留继续工作需要的决定、交付范围和待办。本轮完成用户需求、架构、官方招聘研究、12 项技能规格与实施文档；以[产品需求与验收](PRODUCT_REQUIREMENTS_ACCEPTANCE.md)为依据，按[重构方案](REFACTOR_DESKTOP_TEAM_RAG.md)渐进实施。代码现状和历史运行结果分别见源码及[验证记录](WORKBENCH_VALIDATION.md)，文档规格不代表已运行能力。

## 1. 已确定的目标

- 产品名称：**律序 · LexOrder**。
- 用户仓库：[zaenzhang/LexOrder](https://github.com/zaenzhang/LexOrder)，主分支 `main`。
- 用户已授权：核实开源项目、制定融合计划、在云环境搭建、提交并上传完整源码与方案；不需要再次询问是否上传。
- 面向个人律师和团队：既提供个人可独立使用的安装包，也支持团队自行部署协作，尽可能保留既有业务功能。
- 个人版与团队版都必须有 RAG；RAGFlow 是可选引擎，可以连接团队共享实例或官方托管服务。优先验证内置检索，模型本地/云端配置与完整离线分别处理。
- 默认保留 Next.js / TypeScript / Prisma / PostgreSQL。M1 首先验证 Electron + 标准 Node/Next + 原生 PG，以及 TS 内置 RAG；LanceDB 是首个候选。Tauri/局部 Rust 由明确需求和实测收益触发，全面 Rust 与 SQLite/PGlite 迁移延期。
- 用户需求主线：目标/客户指示 → 材料 → 事实/争点 → 带来源草稿 → 律师确认 → 行动/客户跟进 → 实际交付/归档。重点是恢复上下文、核查依据、落实责任；首发聚焦中国大陆个人律师与小团队民商事诉讼、仲裁，保留其他现有事项类型。
- 参考 ANQI、Paperless 等项目的核心规则与处理逻辑；全球律所官方招聘与培养资料补充研究、判断、表达、协作和交付技能。资料到产品技能的映射是设计判断，学历/执照不能由技能代替。本轮用户明确要求落文档并提交。
- 固定基线：LawLink `v2.0.1`，提交 `4736aa100515bb15f47443cdb6b0ae65745e5fff`。保留 MIT 许可、原版权和来源。
- 当前实现仍为 Next.js / React / TypeScript / Prisma / PostgreSQL，单实例业务系统；桌面发行、统一 RAG 和技能执行器尚未实现，不把候选路线或技能规格当作已发布功能。
