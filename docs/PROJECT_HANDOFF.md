更新日期：2026-11-16。本文压缩此前「律师工作台方案」对话，只保留继续工作需要的决定、交付范围和待办。具体证据以本仓库当前代码及[验证记录](WORKBENCH_VALIDATION.md)为准；最新交付与重构决策见[个人安装版、团队版与 RAG 评估](REFACTOR_DESKTOP_TEAM_RAG.md)。

## 1. 已确定的目标

- 产品名称：**律序 · LexOrder**。
- 用户仓库：[zaenzhang/LexOrder](https://github.com/zaenzhang/LexOrder)，主分支 `main`。
- 用户已授权：核实开源项目、制定融合计划、在云环境搭建、提交并上传完整源码与方案；不需要再次询问是否上传。
- 面向个人律师和团队：既提供个人可独立使用的安装包，也支持团队自行部署协作，尽可能保留既有业务功能。
- 个人版与团队版都必须有 RAG；RAGFlow 是可选引擎，可以连接团队共享实例或官方托管服务。优先验证内置检索，模型本地/云端配置与完整离线分别处理。
- SQLite 只是业务库选项之一，保留 PostgreSQL；Rust/Tauri 为重点重构评估路线，具体模块、默认存储和性能结论待原型验证。
- 参考 ANQI、Paperless 等项目的核心规则与处理逻辑，提炼行为规格后在 LexOrder 独立实现；本轮用户要求将结论落入项目文档。
- 固定基线：LawLink `v2.0.1`，提交 `4736aa100515bb15f47443cdb6b0ae65745e5fff`。保留 MIT 许可、原版权和来源。
- 当前实现仍为 Next.js / React / TypeScript / Prisma / PostgreSQL，单实例业务系统；新交付形态与 Rust 路线尚未实现，不把评估结论当作已发布功能。

3. 优先验证 R2/R3：内置 RAG 的导入、解析、混合检索、回答、版本引用、撤回及恢复；验证个人安装与团队集中运行，之后收敛 Rust/存储/模型方案。
4. B03 今日计划与客户全景、B05/B06 原文锚点和多来源事实继续纳入业务范围；个人计划日期与正式期限保持独立。
5. B07—B09 按必备 RAG、首家已授权法库、引用和 AI 建议确认推进；RAGFlow 为可选适配，不能成为个人使用的强制前置服务。
