# LexOrder 重构方案：TypeScript 主线、个人安装、团队协作与专业技能

更新与核验日期：2026-11-16。

**决策：共用 TypeScript 业务能力，部署版保留 LawLink / Next.js / Prisma / PostgreSQL 基线；个人版以独立运行、最小组件和资源预算决定本地运行时与存储。正式 release 至少同时提供个人安装包和服务部署产物，两个版本均必须有内置 RAG。Rust 不作为默认全面迁移目标。**

本轮交付为需求、架构、招聘能力研究、技能规格与实施计划文档。尚未实现桌面安装包、统一 RAG、技能执行器或本文拟增的业务模型。初始评估为 `97867e2`；提交前已对齐 main `2997b54754565081271ca4b66139949d310e2fe0`，保留刚合入的二开增强与验证记录。此前的 Rust 优先评估由本文更新，历史内容可查 `97867e2` 中的旧版文档。

同日用户进一步明确 release 必须提供最小化个人运行版和部署版。本次在文档提交 `c43608a` 上修订个人运行时边界；完整产物、资源目标及发布证据见 [Release 双版本与资源预算](RELEASE_VARIANTS_AND_RESOURCE_BUDGET.md)。其中内存与启动指标为待实测的工程目标，不能作为现有性能声明。

## 1. 已确认的产品目标

用户补充的[产品需求与验收基线](PRODUCT_REQUIREMENTS_ACCEPTANCE.md)是工程决策的依据：

- **恢复上下文**：目标、指示、事实、风险、最新决定、等待与下一步。
- **核查依据**：材料、法律来源、版本、反向证据与人工判断可以追溯。
- **落实责任与结果**：期限、任务、客户决定、复核、实际交付及费用相互关联。

首发聚焦中国大陆个人律师和小团队的民商事诉讼、仲裁，同时保留合同审查、顾问等既有事项类型。核心仍是 Matter，不因产品使用“法律事项”而更换数据身份。

首条完整验收流程：

**目标与指示 → 材料入库 → 事实与争点 → 带来源草稿 → 律师确认 → 行动与客户跟进 → 交付归档。**

全球律所招聘研究用于把研究、判断、表达、协作与交付能力内化为[专业技能](LEGAL_SKILLS_CATALOG.md)。技能共用上述数据链，不能把产品简化成多个彼此独立的聊天助手。

| 目标 | 本轮决策 |
| --- | --- |
| 个人独立 | 最小化安装包，本地核心流程不依赖团队服务器；运行时、数据与模型按资源预算管理 |
| 部署与协作 | 可自行部署或代管独立实例，服务端集中鉴权与处理，普通成员只需浏览器 |
| 正式 release | 同版本提供 Personal 安装包和 Server 部署产物；两个产物分别验收 |
| RAG 必备 | 个人和团队共同能力，默认内置，RAGFlow 可选 |
| 保留业务 | 继续使用客户、收案、事项、权限、期限、财务、审批、文书和归档 |
| 技术主线 | TypeScript 持续承担共用业务和编排；部署版保留现栈，个人运行时/存储单独验收 |
| 法域扩展 | 共用工作结构，分离语言、准据法、程序法域、机构、时区与处理地区；逐法域验收 |

个人独立与完全离线分别验收。完整离线还要求 OCR、嵌入、必要重排、生成模型与运行时均已准备好。跨设备双向离线同步、共享 SaaS 和多国规则同时上线不在首发范围。

## 2. 推荐的交付方式

### 2.1 同一业务核心，两种运行入口

| 层 | Personal：最小化个人运行版 | Server：服务部署版 |
| --- | --- | --- |
| 界面 | 复用 React 及可复用页面，桌面外壳按目标平台实测选择 | 浏览器；桌面可连接团队地址 |
| Web 与业务 | 共用 TS 服务；本地 Next/Node 或精简入口由兼容与资源原型决定 | Node + Next 服务，复用现有入口 |
| 业务数据 | 应用托管单机存储；原生 PG 为兼容对照，嵌入式候选须保留业务语义 | PostgreSQL |
| 材料 | 本机私有目录，程序与用户数据分开 | 持久卷或已有 StorageProvider 支持的存储 |
| 后台执行 | 同仓 TS worker，应用管理生命周期 | 同仓 TS worker，可与 Web 分进程 |
| 检索 | 第一候选 LanceDB Embedded，由指定进程管理 | 首期同一适配器，单个索引写入所有者 |
| 模型 | 云 API 或按需本地组件；默认不附带/常驻生成大模型 | 管理员配置本地推理服务或云 API |
| 恢复 | 应用内备份、升级和恢复向导 | 管理员一致备份、恢复和监控 |

这是**模块化单体、同一代码库、可分进程运行**的方案。Web、worker、桌面管理入口不各写一套权限和业务规则。重 OCR/分块/嵌入移出交互请求，避免占用 Web 请求处理。

正式发布物必须包括独立个人安装包及固定版本镜像/部署配置包。远程浏览器、PWA 或桌面连接入口只属于部署版访问方式，不能替代个人运行版。Next.js 支持 Node、Docker 和不同托管平台，使用当前栈不等于只能由最终用户自行运维。[N3]

桌面“连接团队”时，团队服务器是该工作区的数据权威来源，远程页面不取得个人文件和数据库权限。个人迁入团队通过明确导入、用户映射和权限复核处理，不依赖共享数据库文件夹。

现有 `tools/cloud-dev/run.mjs` 已管理 Node 与原生 PostgreSQL，但它是开发验收工具、关闭 cron/自动备份，不能直接称为桌面安装器或生产托管方案。[B6]

二开已提供独立 cron worker、Web/worker 联合监督器、启动补扫及备份 CLI，可作为进程管理基础。启动补扫只有计划时刻后 15 分钟窗口，其他作业仍依赖单实例，不能据此宣称完整休眠恢复或分布式任务安全；成功备份/恢复仍未演练。[B8]

### 2.2 先测兼容基线，再确定个人版组件

保留现有动态页面、Server Actions、NextAuth、Prisma 和 Office 处理链时，Electron + Node + 原生 PG 是低迁移成本的对照原型。这不证明它满足个人版轻量要求，也不预先锁定为发行架构。M1 使用发布构建测完整进程树，再选一个轻量候选作同场景比较，不同时实现多套正式后端。

Next.js 静态导出不支持 Server Actions、cookies 及依赖请求的路由等当前使用能力；应保留真实服务端运行时。优先验证 standalone，当前仓库尚未配置该输出。其静态资源、public、运行配置、迁移文件、Prisma 引擎和原生包需明确打包，不能假定自动追踪全部完备。[N1][N2]

Tauri 官方也提供 Node sidecar，可作为个人版外壳候选，并不要求重写业务为 Rust。外壳替换、精简本地服务入口、单机存储适配分别评价；Tauri 不会自动消除仍保留的 Node、数据库或模型占用。[T1]

个人基础档先以 8 GB 内存、SSD、无独显的办公机为目标；空闲全进程专用工作集不高于 500 MiB、常用业务峰值不高于 1 GiB、已初始化工作区冷启动不超过 5 秒，是首轮工程预算，尚未实测。完整测量口径及材料处理档见[资源预算](RELEASE_VARIANTS_AND_RESOURCE_BUDGET.md#3-个人版基础档的资源目标)。未达标时优化组件、并发与生命周期，再决定数据库/运行时，不直接抬高基础配置。

### 2.3 桌面原型必须解决的问题

优先用干净 Windows x64 普通用户环境验证；macOS/Linux 按实际完成的机器与架构逐项加入支持清单。

- 不依赖用户预装 Node、数据库、Docker 或模型开发工具；验证中文/空格目录、安装目录迁移和原生依赖加载。
- 明确标准 Node 子进程与 Electron 自身 Node 的边界。原生模块直接加载于 Electron 时涉及 ABI/构建兼容，不能推定二者等价。[E2]
- 数据库首次初始化、约束与守卫、重复启动、异常退出、升级与卸载保留数据均可解释；使用独立进程时另验锁文件与端口占用。
- 使用本机 HTTP 服务时仅绑定回环地址，同时处理身份、会话、启动凭据、Host/Origin、CSRF、NextAuth 回调与 Server Actions 来源校验；回环地址本身不提供授权。采用 IPC 时同样重验身份与调用资格。
- 若采用 Electron，关闭渲染器 Node integration，启用 context isolation/sandbox；任一外壳的桥接/IPC 都须最小授权并验证调用来源，远程团队页面不获得个人工作区能力。[E1]
- 应用休眠或关闭时，本机作业不继续；恢复后补扫到期事项、恢复任务并去重。持续运行的团队服务负责其在线作业。
- 备份覆盖数据库、原件、必要配置和可恢复密钥；数据库与文件形成一致恢复点。采用 PG 时不能直接复制正在写入的数据目录，采用嵌入式库也须使用对应一致性方法。
- 数据格式升级与应用更新分别验证；采用 PG 时大版本按独立迁移流程处理，不能仅替换二进制。失败后保留可恢复副本。[P1]

## 3. RAG 必须有，优先内置一个引擎

### 3.1 先验证 LanceDB 的 TypeScript 适配

LanceDB 官方 JS SDK 可连接本地路径，并下载目标平台原生库。TS 可以组织授权、任务、分块、模型调用与引用，而检索由成熟底层执行；没有必要为使用原生搜索内核重写整套业务。[L1]

首期只实现一个 `RetrievalProvider`。在固定版本上验证全文/向量混合检索、过滤、中文效果和目标平台打包；文档或 main 的新功能不自动等于选定稳定版可用。

中文姓名、简称、完整/局部案号、条款编号、金额、日期、同义表达和中英混排单独评测。默认 simple 分词按空白与标点切分，不能直接宣称具备合格中文分词；按版本验证 ICU 或预分词策略。[L2]

首期明确一个索引进程负责写入与代次切换，Web 通过私有内部接口调用。多进程读写、共享网络磁盘、多服务节点和高可用须另行验证，不将 Embedded 当作分布式服务。

### 3.2 同一管线，三类来源

| 范围 | 业务意义 | 首发要求 |
| --- | --- | --- |
| 当前事项材料 | 支持事实、陈述与证据分析 | 具体 Document 版本、锚点、覆盖与材料/AI 权限 |
| 获授权法律资料 | 支持法律规则与分析 | 法域、来源类型、效力角色、相关日期、有效期间、检索时间、原始 ID/链接与实际权益 |
| 个人/律所经验 | 支持方法与模板复用 | 显式选入、脱敏、审核、适用条件、受众、版本和失效状态 |

可以共同检索，但输出须说明来源性质。经验库不自动吞入所有历史案卷；同一律所不等于全部成员有权访问全部案件。

首家法库从现有元典能力扩展；提供商不支持、未授权、限流、超时和无结果分别表达。无真实账号时允许用获授权的用户材料验证引用契约，不将其标为商业接口已联调。

### 3.3 处理、检索、回答是不同阶段

原件保存 → 页/段/表格解析与 OCR → 分块 → 词法/向量索引 → 权限内召回 → 引用与覆盖快照 → 生成候选 → 律师复核。

通用文本提取已覆盖文本 PDF、DOCX 和文本，但扫描 PDF 当前可能进入 SKIP；短信 OCR 是可复用的另一条管线。二开又加入传票首页文本提取、可选本地 OCR 与视觉模型回退，本地扫描处理依赖另配工具。它们仍需统一页级状态和位置信息，不能把局部 OCR 路径写成通用 OCR 已完成。[B2][B8]

现有 AI 文书审查有分段、截断和数量限制，仍包含请求内执行；新增工作要补真实阅读覆盖和可恢复作业。检索到若干片段不等于读完全部案卷。[B3]

### 3.4 模型位置独立配置

| 配置 | 外发边界与可用性 |
| --- | --- |
| 本地 OCR/嵌入/生成 | 所需模型准备后分别验收断网能力 |
| 本地检索、云端生成 | 问题和被选片段会发送到生成服务 |
| 云端 OCR/嵌入 | 原始图像或对应文本在该阶段外发，即使索引保存在本地 |
| 团队本地推理 | 由团队配置地址和授权，不能仅凭“自部署”判断所有阶段都在内网 |

现有 AI/HTTP OCR 使用的 URL 校验拒绝回环和私网地址，AI 配置完成判断还依赖 API key。新增受信本地 provider 要有独立、精确的地址/端口与认证策略，不通过全局放开 URL 检查实现本地连接。[B4]

应用管理模型下载、完整性、存储占用、失败恢复和离线导入。AnythingLLM 的桌面/团队交付与内置 LanceDB、Cherry Studio 的模型管理可作为流程参考，不构成 LexOrder 已完成的证明。[A1][A2][C1]

模型不可用时保留材料管理和已验证的关键词检索；查询嵌入、重排和生成分别显示依赖状态，已有向量不代表离线语义检索自动可用。

### 3.5 其他引擎的启用条件

| 方案 | 本轮定位 | 恢复排期的依据 |
| --- | --- | --- |
| RAGFlow 自部署/托管 | 可选远程适配 | 已验证复杂解析或规模需求值得承担额外服务 |
| PostgreSQL + pgvector | 团队备选 | 内置引擎在具体负载、治理或部署上出现可测限制 |
| SQLite FTS/向量扩展 | 轻量检索备选 | 默认引擎的目标平台或资源问题无法满足指标 |
| SQLite/PGlite 业务库 | 个人版轻量候选；不替换部署版 PG | 与对照原型比较资源，并证明数据库语义、迁移和恢复；不是零改动替换 |

RAGFlow 的文档筛选、空列表、汇总片段语义须按实际接入版本联调。沿用此前研究中的防线：LexOrder 在空授权时直接返回空；关闭未经证明全部来源已授权的知识汇总。外部引擎权限不替代本地业务授权。相关来源保留于 [UPSTREAM_SOURCES.md](UPSTREAM_SOURCES.md)。

## 4. 为什么 TypeScript 是当前主线

| 比较项 | 保留 TS / Next / Prisma | 全面 Rust 迁移 |
| --- | --- | --- |
| 业务规则 | 增强已存在服务与事务 | 重写并重新证明状态、金额、审批、权限行为 |
| Web 界面 | 保留 RSC、Server Actions、会话与页面 | 重划接口与鉴权边界，适配页面调用 |
| 文档生态 | 复用现有 DOCX、PDF、表格、模板工具 | 验证替代库或仍需辅助进程 |
| RAG | TS 编排 + 成熟原生组件/模型服务 | 编排本身需重写，OCR/模型速度不因语言自动改善 |
| 交付成本 | 新增桌面托管与安装工程 | 同时承担语言、接口、数据库与交付变化 |
| 当前决定 | 作为持续业务主线 | 暂停整域迁移，按局部测量结果重新评估 |

这是针对当前仓库资产的成本/风险判断，尚无可据以报告的开发速度倍数或性能对照数据。

重构的重点是：从请求入口拆出可复用业务服务、统一材料处理和引用、补齐可恢复任务、接通工作链。按正在修改的功能逐步提取，不先全仓搬目录，不引入新的通用 ORM/工作流框架作为前置。

Server Actions/Route Handlers 保留会话、输入校验和页面刷新；业务服务接收显式 actor/context，事务内复核权限与版本；worker 调用相同服务。抽出服务不代表移除现有事务内权限检查。

Rust 的后续使用条件：已知热点经 profiling 证明是本模块 CPU/内存问题，成熟原生库或任务拆分仍不能达标；或某项原生集成确有收益。以小接口替换该组件，再跑同一验收包。

## 5. 必须保留的现有资产与数据语义

| 现有事实 | 处理决定 |
| --- | --- |
| ClientActivity / ClientFollowUp 已实现 | 补聚合、指示与等待，不再列为从零新增 |
| EvidenceItem 已有五类要点、单来源/页码 | 加多来源、支持/反驳、发生时间与确认 |
| Document 一行一个版本，familyId 串联 | 引用绑定 Document.id + sha256，不造平行 DocumentVersion |
| 文书送审、批准、驳回和入卷已有 | 补引用复核与版本绑定交付，不新建替代审批系统 |
| Task / WorkResponsibility / 交接已有 | 补依赖、等待对象、检查日和计划日期 |
| 期限人工保护、正文搜索、提醒台账已有 | 增强来源和覆盖，保留原语义 |
| 财务、权限、归档使用 PG 事务与守卫 | 部署版保留 PG；个人存储适配必须证明相同业务约束和恢复行为 |
| 现有 AI、审查历史、外发日志 | 新 AiRun 与旧记录建立明确映射，逐步统一 |
| StorageProvider 已有 local/S3 抽象 | 复用文件契约；派生 OCR/索引/缓存也要纳入保护 |
| 元典法规/cncases 界面、执行模板、传票首页解析与独立调度已合入 | 复用并按实际权益、覆盖和恢复边界扩展，不重复列为从零建设 |

代码依据见 [B1]—[B8]。PG 耦合包含数组、JSONB、Decimal、行锁、advisory lock、部分唯一索引、函数、触发器及 CHECK；不能只改 Prisma provider 即完成 SQLite 迁移。PGlite 官方说明其 socket 多连接由单连接多路复用实现，不保证正常 PG 的所有用例，因此也不能当作现有 Prisma/并发队列的零改动替换。[P2]

现有 `JobQueue` 已有去重、租约与重试，但完成更新仅按 id + RUNNING，尚无领取所有权 token。长 OCR/嵌入前补 token、续租、按 token 条件提交、取消和检查点；旧 worker 迟到不能结束新的领取。领取批次和并发限制要匹配实际处理能力，避免任务在队列内等待时租约已经耗尽。[B5]

## 6. 统一业务与技能契约

### 6.1 最小增量

| 概念 | 设计边界 |
| --- | --- |
| 事项上下文记录 | 目标、客户指示、备选方案、决定/理由、来源与版本；复用现有范围和描述 |
| MatterBrief | 授权范围内聚合视图，不复制状态和责任人的权威值 |
| SourceAnchor / EvidenceSourceLink | 具体文档版本、页段/表格位置、多来源与关系 |
| Evidence 关系 | 支持、反驳、矛盾、待核实；首期用关系表/字段即可 |
| 任务等待/依赖 | 复用 Task 和责任链，外部等待仍需内部负责人 |
| 解析运行 / DocumentIndexBinding | 解析/分块版本，嵌入 provider、模型 ID/修订、输入处理配置及维度的完整指纹，索引代次、覆盖和状态 |
| AiRun | 技能/模型/提示版本、实际材料版本与输入范围、工具调用、覆盖和引用 |
| 建议契约 | 结构化候选和目标版本；先适配 SmsSuggestion 等现有对象，不先建设通用流程引擎 |
| DeliveryRecord | 审核后的确切成果版本、对象、渠道、实际交付证据、客户确认与替代关系 |

名称为设计草案，具体表和迁移在相应实现任务中确定。保留主键和旧字段语义，按兼容增量实施。

### 6.2 权限、版本与确认

1. 全文、向量两路都使用服务端计算的授权范围；空范围直接结束。送入模型、输出、历史读取与打开引用时复核当前权限。
2. 案件概况、材料全文、AI 处理、财务、审批和导出分别授权。团队汇总只读或系统管理员身份不能替代这些资格。
3. 文档/权限撤回后立即失效相关待执行和进行中的任务；后续外发、结果交付及缓存提交再次核对。已经发送的内容不能承诺收回。
4. 引用绑定具体版本与锚点。新版本提示受影响的分析/文书，旧引用不静默改指最新版本。DOCX 用真实段落/字符或转换映射，无法定位时明确说明。
5. 索引代次绑定解析/分块版本，以及嵌入 provider、模型 ID/修订、影响嵌入结果的输入配置和维度组成的完整指纹。同维度不代表向量兼容；配置切换须建立新代次，完成后原子切换，不混查不兼容向量。删除、取消或旧代次迟到不得重新发布；验收覆盖模型切换及重建失败。备份权威数据及必要组件后，索引允许重建。
6. AI 输出是候选。通过类型与来源校验、人工复核，再由既有业务服务写入；事务内复核操作者、目标版本、幂等与状态。
7. 草稿生成、内部审核、正式提交/交付和客户确认分别记录。技能默认形成可审阅成果，不凭模型输出自动承诺、付款、发送或提交法院。
8. 知识发布必须显式选入并完成脱敏和审核；历史 AI 成果与缓存不能绕过当前访问资格。
9. 材料版本/处理代次变更与待执行任务须同事务落库，或同事务写 outbox 再可靠投递，并有补扫。提交 Document 后、入队前崩溃的任务不会靠租约恢复自动出现；现有入队接口需要支持事务上下文或被可靠投递层封装。

### 6.3 技能如何进入 TS 架构

首期使用版本化技能定义 + Zod 输入/输出契约 + 明确工具清单 + AiRun，复用模型/provider/队列。每项技能具备需求编号、适用范围、输入前置、处理步骤、产物、引用规则、人工复核和评测。

工具由服务端注入已授权的资料读取、检索、模板和候选动作能力；权限范围不由提示词或模型传入的文档 ID 决定。技能定义及版本随代码审查，输出回到 EvidenceItem、研究记录、文书候选、Task/跟进候选或交付草稿。

先将首条工作流程中的技能接通，再根据质量证据增加复杂编排；不以通用 Agent 平台或多代理角色数量作为交付目标。具体规格见 [LEGAL_SKILLS_CATALOG.md](LEGAL_SKILLS_CATALOG.md)，招聘依据见 [LAW_FIRM_COMPETENCY_RESEARCH.md](LAW_FIRM_COMPETENCY_RESEARCH.md)。

### 审查与发布门槛

- **产品**：按 RQ 编号检验上下文、依据、责任与交付；不是只验 API 或聊天。
- **权限/数据**：无权召回、缓存/历史泄漏、空授权扩大、引用漂移、旧代次发布、未经确认正式写入作为阻断问题。
- **作业/恢复**：并发领取、续租、中断、重试、取消、唤醒、备份及重建针对实际故障验收。
- **专业质量**：关键事实和反证遗漏、引用是否支持论断、法律来源/时点、草稿返工和客户简报准确性由律师对样本评定。
- **交付**：每个正式 release 同时具备个人安装包与部署产物；目标平台真实安装/更新/恢复，所选运行时、存储和守卫可用。
- **性能**：按资源预算测基础、材料处理和可选模型三档的全进程占用，记录冷启动、P50/P95、吞吐和积压；明确硬件/材料规模，不将设计目标写成实测配置。
- **审查节奏**：每批聚焦变更及既有回归；新发现分类进 backlog，阻断项先修，不扩成无限全仓重审。

本轮仅执行代码/官方资料核查与文档一致性检查，历史测试数量不用于证明上述新增能力。后续代码变更沿用仓库 lint、typecheck、Prisma、生产构建及受影响行为验证；有界面改动时执行完整点击流程。

## 9. 已定、待证与延期

**已定**：共用 TS 业务能力、部署版保留 PG、正式 release 两种可选产物、个人独立且按资源预算验收、内置 RAG 必备、三类来源区分、人工复核与交付留痕、技能版本化。

**M1 必须回答**：个人运行时/外壳/单机存储的兼容与资源对照，所选存储的迁移/守卫/恢复；固定 LanceDB 版本的中文/权限/平台表现；本地 provider；模型按需管理。结果决定个人版组件、版本与支持平台。

**延期**：全面 Rust、替换部署版 PG、多个检索后端同时开发、离线多人同步、多租户、通用工作流/Agent 平台、多法域同时发布。个人版必要的嵌入式存储适配属于 M1 选型及后续有界实施，不再一律延期，也不据此重写全系统。
