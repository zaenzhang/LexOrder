# 案情提取提示词 /9 与 /11 对照 · 2026-11-20

六类合成案卷各做两轮。每轮同一案卷分别使用 /9 和 /11，同一供方保持模型、输出契约、材料和生成参数固定。正式实验共 48 次请求，全部返回 `stop` 并通过响应结构读取。另有两次先行的接口探测，未计入正式样本。六类案件为借款交付、设备采购、劳动补偿、工程结算、租赁解除和保险赔款。

## 逐项通过率

每家每版 12 次请求、66 个预设检查。检查看候选经过 LexOrder 的固定原文定位和规范化后是否保留所需证据。否认检查同时计入陈述归属、标题是否保留极性和是否生成正向付款。金额检查同时覆盖精确数值、币种、金额性质和上限或近似值是否被误当定值。日期检查覆盖角色、日或月精度、起止区间及不确定性。工资表的覆盖月份没有指定日期角色，只检查是否保留到月。

| 模型 | 证据措辞 | 否认 | 金额 | 日期 | 全部 |
| --- | ---: | ---: | ---: | ---: | ---: |
| OpenAI GPT-6.2 Sol | 20/20 → 20/20 | 11/12 → 12/12 | 12/16 → 14/16 | 16/18 → 16/18 | 59/66 → 62/66 |

## 样例复核

- **金额的提升主要来自保住限定语。** 租赁案的「每期不超过3万元」在两家 /9 的四次请求都变成精确的 30,000 元。/11 四次均保留了上限语义，且未生成精确金额。
- **否认的提升包括更清楚的显示和分句。** OpenAI /9 有一轮候选标题写「补偿收款陈述」，正文实际是「从未收到补偿」。DeepSeek /9 有一轮把「否认收到12万元」和「认可另笔2万元」放在同一条，标题也没有体现否认。/11 两家的否认检查均通过。这里按标题、归属、引文和关系的组合计分，单项失分不能直接解释成生成了错误付款边。
- **DeepSeek /11 的证据完整性和日期各有回退。** 保险案保留了付款指令作废及未到账，两轮都漏掉「原始回单待调取」。工程结算日期一轮仍留在 2024 年 6 月，但被标成 `AGREEMENT`，本案预期是记录结算动作的月份。
- **两版均未通过借款案的另笔 2 万元金额检查。** /11 能把认可收款另列为一条，但规范金额仍为空。用同一原句离线回放可复现：后端在整行找 `2万元` 时也会命中 `12万元` 的尾部，即使候选已给出唯一的认可分句，金额仍被丢弃。把两处分到不同的编号行后，同一路径可规范为 `CNY 20000`。供应商原始完整回包没有保存，这个离线结果确认了定位机制的缺口，不能判定每个模型回包都发出了该字段。
- **工资归属期仍漏提。** 4 月工资表的月份出现在部分标题或引文中，四组均未填入结构化日期。现有日期角色没有工资归属期，本次仅检验月份是否进入日期字段。

这批样本显示 /11 改善了否认表达和金额限定语，代价是每次总 Token 增加约三成。证据措辞与日期没有同步改善。统计是有限合成样本上的评分，适合定位问题和复跑。完整案卷、重复名称消歧、材料检索覆盖及真实使用成本需另行评估。

## 复现与边界

- OpenAI 请求 `gpt-6.2-sol`，`reasoning_effort=low`，严格 JSON Schema，输出上限 4,200。DeepSeek 请求 `deepseek-flash`，关闭 thinking，`temperature=0`，JSON Object 加同一份内联 Schema，输出上限 4,200。输入形式在各自的 /9 和 /11 之间保持一致。API 模型列表及响应均返回 `deepseek-flash`，官方将其映射为 DeepSeek V4.1 Flash。 [OpenAI 模型](https://developers.openai.com/api/docs/models/gpt-6.2-sol) · [DeepSeek 模型映射](https://api-docs.deepseek.com/quick_start/pricing/)
- 实验驱动直接调用供方 API，再复用 `unpackObservationDraft` 和 `inspectAiObservationResult`。没有模拟 UI、队列、OCR 或本地回单短路，也没有以生产传输开关代替实验配置。跨供方用量含序列化模式和 tokenizer 差异，版本变化以各供方自己的旧版为基线。
- /9 来自改版前源码，/11 来自实验当时的代码。实验驱动读取归档中的两版固定提示词。当前应用已使用 /12，重跑使用当前后处理来核对同样的提示词。完整文本、样本、请求标识、原文校验后的候选、逐项得分与用量均在 [JSON 明细](./prompt-ab-results.json)。评分脚本在 [实验驱动](./prompt-ab.ts)。检测到工资表缺少恰当日期角色后，对两版保存的候选统一按月份精度复算，不重调接口。
- 在仓库根目录配置环境变量 `OPENAI_API_KEY` 和 `DEEPSEEK_API_KEY`，用 Bun 执行 `bun docs/evidence/2026-11-20-observation-openai/prompt-ab.ts`。执行会产生新一轮 API 请求，结果写入仓库根目录的 `storage/observation-prompt-ab-rerun.json`。附加 `--rescore` 仅对原归档中的候选重新评分，并将复算结果写到同一路径。
