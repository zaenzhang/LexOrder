# 案情记载结构化输出 Token 对照

## 实测结果

2026-11-20 使用 OpenAI Chat Completions 实测。对本次三类合成案卷，去掉系统提示中重复的 JSON Schema 后，每次分析少使用 **492 个输入 Token**，平均从 **1,568** 降到 **1,076**，降幅 **31.4%**。

| 请求模式 | 请求数 | 输入 Token | 输出 Token | 缓存输入 Token | 预设检查通过 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 系统提示与结构化参数重复附送 | 12 | 18,816 | 2,790 | 6,656 | 52/52 |
| 只通过结构化参数发送 | 12 | 12,912 | 2,761 | 0 | 52/52 |

`prompt_tokens`包含缓存输入。百分比只描述请求 Token，用量中的缓存列供核对。账单金额与全产品典型降幅需要按实际请求分布另算。

**网页生成单独计量。** 这组对照只测结构化提取。固定前端直接用保存的数据绘制时间轴、矩阵和原文高亮，打开案件、切换视图和调整展示无需为网页布局再调用模型。与模型逐案生成 HTML、CSS 和 JS 相比，这一阶段还省去网页生成的输出 Token 及等待。该阶段的 Token 与端到端耗时尚未做同条件实测，后续应单独记录。

## 条件和判定

- 固定模型版本 `gpt-4.1-mini-2025-04-14`、`gpt-4.1-2025-04-14`，每种案型每个模型跑两轮、每轮配对比较，共 24 次请求。轮次交替 A/B 顺序。温度为 0。
- 两组都使用同一严格 `response_format.json_schema`、同一任务说明与材料。唯一请求差异是系统消息是否再附一份同样的 JSON Schema。记录供方响应的 `usage.prompt_tokens`、`completion_tokens` 和 `prompt_tokens_details.cached_tokens`。
- 对同组模型输出调用产品的候选转换和原文校验，核对日期、借款金额、关系类型及方向、第二份材料的当事人陈述性质和有无凭空关系。两组各 24 条可定位候选，无拒绝或被跳过的字段。两种模型在预设检查上的结果相同。自动检查没有覆盖候选标题措辞、全部潜在事实召回或法律判断。这批样本是短文本合成材料，覆盖借款、设备买卖、劳动用工三种常见结构。
- 数字对应案情记载提取。案级归并也复用单份 schema 的传输规则，本次未计入该对照。

## 复跑

在仓库根目录用已授权的 `OPENAI_API_KEY` 执行：

```sh
node --import tsx scripts/benchmark-observation-openai.ts
```

脚本只发送内置合成文本，输出模型版本、供方用量、请求标识和检查结果。实验当时使用 /9 版提取提示词。脚本重跑使用仓库当前契约和提示词；没有原生 schema 能力的供方由客户端在系统消息中发送一份结构说明。
