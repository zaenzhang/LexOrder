# Release 双版本与个人版资源预算

更新日期：2026-11-16。状态：用户确认的发布要求与待验证的工程验收目标；当前尚未生成这两类发行产物，也没有个人版资源实测结果。

用户明确要求：**每个正式 release 至少提供两个可选产物——最小化个人运行版、服务部署版。** 本文补充[产品需求](PRODUCT_REQUIREMENTS_ACCEPTANCE.md)，并修订[架构方案](REFACTOR_DESKTOP_TEAM_RAG.md)中个人运行时与存储的选型边界。

## 1. 两种可选发行产物

| 项目 | Personal：最小化个人运行版 | Server：服务部署版 |
| --- | --- | --- |
| 使用方式 | 安装后建立本地工作区，个人独立使用 | 在一台主机或云环境部署，个人/团队通过浏览器访问 |
| 安装产物 | 至少一个已验证平台的安装包；首个目标为 Windows x64 | 固定版本应用镜像、Compose 配置包、示例配置及部署/升级/恢复说明 |
| 用户前置 | 不要求另装或维护 Docker、Node、数据库、RAG 服务 | 管理员提供部署主机、持久存储和必要配置；普通成员只需浏览器 |
| 核心运行 | 核心事项、客户、材料、任务、文书和记录不依赖团队服务器 | 共享业务核心，集中鉴权、存储、后台处理与审计 |
| 数据 | 原件、业务数据及索引在本地工作区，应用负责生命周期 | PostgreSQL 与持久文件/对象存储，管理员负责集中运维 |
| RAG | 内置检索管线与模型配置，支持云 API 或按需本地模型 | 同样内置 RAG，模型/索引由团队集中管理；RAGFlow 可选 |
| 生成大模型 | 默认不附带或常驻；用户选择后安装或连接 | 独立配置模型服务或 API，不要求业务服务器同时运行生成模型 |
| 版本关系 | 与 Server 使用相同 release 版本，声明数据格式和能力范围 | 同左，提供经过验证的迁移/导入路径 |

个人版的“最小化”指默认运行组件、常驻资源与安装维护负担。既有事项身份、材料版本、财务和审批语义继续保留；适用功能有差异时列出能力表，不静默丢失数据或跳过业务守卫。

访问远程实例的浏览器、PWA 或桌面客户端属于部署版的访问入口，**不能计作独立个人运行版**。正式 release 必须同时具备上述两类可用产物；只有一种通过时可发布注明范围的 prerelease，不标记双版本正式发布完成。GitHub 自动生成的源码压缩包不替代可运行的部署产物。

### 产物命名示意

- `LexOrder-Personal-<version>-windows-x64-setup.exe`：首个候选平台；其他平台只在真实安装/升级/恢复通过后加入。
- `LexOrder-Server-<version>.tar.gz`：包含固定镜像版本或摘要的 Compose、配置模板和运行说明。
- `release-manifest.json`：版本、平台、文件校验值、镜像摘要、数据格式/迁移版本、依赖组件、实测环境与资源报告链接。

以上是交付契约，不表示当前仓库已经建立对应流水线、镜像或下载地址。

## 2. 服务端基线与个人实现分开决定

**保留 TypeScript 业务能力，不等于要求每台个人电脑常驻完整 Next.js/PostgreSQL 服务组合。**

部署版继续使用现有 Next.js / TypeScript / Prisma / PostgreSQL，复用权限、事务、模板和数据库守卫。Next.js 可以直接作为 Node 服务或通过托管平台运行，Docker 是一种交付方式，并非框架强制要求；代管一个独立实例也不要求先建设共享 SaaS。[N1]

个人版共用 TS 业务规则、数据契约和可复用 UI，本地 Web 运行时、外壳及业务存储由资源和兼容性原型决定。当前代码依赖 Server Actions、服务端会话和动态页面；转成静态界面需要真实的服务入口改造，不能仅改导出配置。[N2]

| 候选路线 | 作用 | 必须证明的内容 |
| --- | --- | --- |
| 现有 Next/Node + 原生 PostgreSQL | 低迁移成本的兼容与资源对照原型 | 全进程资源、安装生命周期及核心流程；未经资源验收不定为个人版发行架构 |
| 保留精简 Next/Node，替换桌面外壳或单机存储 | 尽量复用动态界面与现有 TS 服务 | 实际减少的资源；原生依赖、会话、迁移与数据库语义兼容 |
| 客户端 React + TS 本地服务 + 嵌入式存储 | 当完整服务运行时无法达标时的轻量实现候选 | 有界拆分 Server Actions/会话依赖，复用领域规则；保证财务、权限、版本与恢复一致 |

嵌入式业务库候选可包括 SQLite 或 PGlite。SQLite 无独立数据库服务进程；PGlite 提供嵌入式 PostgreSQL，但其单连接及 socket 适配限制需要验证。[S1][P1][P2] 本仓存在 PG 数组、JSONB、Decimal、锁、SQL 函数/触发器和守卫，不能只改 Prisma provider。迁移工作应列清需要适配的行为，不以“兼容 SQL”替代验证。[B1][B2]

Electron 有 Chromium 多进程成本，Tauri/系统 WebView 可以作为外壳候选；更换外壳不会自动移除保留的 Node、数据库或模型成本。[E1][T1] TS 与 Rust 的选择是另一层决策，不安排全面语言重写作为轻量化的前置。

先用两个有明确差异的原型回答资源问题，不同时实现三套正式后端。M1 先测兼容对照路线，再选一个最有希望满足预算的轻量候选作同场景比较。若原有组合已满足目标，也必须提供应用托管、无手工维护的个人安装体验。

## 3. 个人版基础档的资源目标

以下数字是**首轮工程验收目标，不是当前实测结果或已经发布的最低配置声明**。用于约束原型与选择运行时；后续调整须记录场景、测量和理由，不能在未优化前直接抬高最低硬件要求。

参考目标机：Windows x64、4 个逻辑 CPU、8 GB 内存、SSD、无独立显卡。具体 CPU 型号、系统版本、可用内存及后台负载在报告中固定。构建在开发/CI 环境完成，用户电脑运行发布产物。

| 场景 | 首轮目标 | 测量边界 |
| --- | --- | --- |
| 启动后空闲 | 全应用专用工作集合计不高于 500 MiB | 无处理任务、无本地模型加载，界面稳定后观察 60 秒 |
| 常用事项工作 | 峰值不高于 1 GiB | 固定的客户/事项浏览、编辑、任务和文书操作工作包 |
| 冷启动 | 已初始化工作区至可操作界面不超过 5 秒 | 首次安装/迁移和首次索引另列，不从启动数据中隐去 |
| 基础后台空闲 | 平均 CPU 不高于整机 1% | 无到期作业的固定观察窗口；报告是否仍有隐藏常驻进程 |
| 材料处理档 | 先以峰值不高于 2 GiB 为约束 | 单并发、分批解析/OCR/嵌入；包含所用小模型，另记录耗时和磁盘增长 |

Windows 使用整个应用及其子进程的专用工作集；其他平台采用明确记录的等价指标，例如 PSS。不得只测 Node heap、忽略数据库/索引/WebView 子进程，或将共享内存重复累加后与不同口径比较。安装下载大小、安装占用和外部运行时下载分别报告，即使已有 WebView 运行时也不能隐去首次安装的最坏情况。

M0/M1 准备固定合成材料工作包，记录事项/文件数量、总页数、文件大小、扫描比例、语言、模型和分块配置；普通工作与批量导入分别测量。使用发布构建和真实目标设备，云端 HTTP 冒烟或开发服务器占用不能替代个人版结果。

资源超预算时依次检查：不必要的常驻组件、重复进程/连接、未裁剪运行依赖、全量读入、OCR/嵌入并发和模型卸载；再决定是否替换外壳、Web 运行时或单机存储。保持业务行为的比较基线。

## 4. RAG 与离线能力分档

两个版本均提供内置 RAG；个人安装包无需因此默认携带生成大模型。解析、OCR、嵌入、检索、重排、生成的组件与外发边界逐项显示。

| 档位 | 可承诺的能力 | 验收条件 |
| --- | --- | --- |
| 基础本地工作 | 核心事项、材料、文书与记录离线可用 | 不依赖团队服务；模型断开时保留普通业务和已有关键词搜索 |
| RAG + 云 API | 本地索引/材料与用户选定的模型服务协作 | 配置可用 provider 后通过带来源问答；标明哪些文本/图像外发；不称完全离线 |
| 本地检索组件 | 按需准备本地嵌入及必要处理模型 | 断网验证查询、索引及重建；单独报告资源，已有向量不代表查询嵌入可用 |
| 全离线 AI | 所需 OCR、嵌入、重排、生成模型均可本地运行 | 指定模型/版本/量化/上下文和设备，实际断网通过后再声明支持 |

provider 未配置时展示明确设置入口及不可用状态，不伪造成功回答。正式 release 两种产物都须至少在一组可用 provider 配置下完成同一 RAG 引用验收；仅提供全文搜索或空的模型设置页不能满足 RAG 门槛。

本地生成模型的权重、上下文与并发会额外占用内存，单独制定硬件说明，不能混进基础版最低配置；模型按需加载、可停止和卸载。[O1] 部署版也将模型服务与业务服务器容量分别估算，不以模型最低显存要求作为普通浏览器客户端要求。

## 5. Release 必须具备的证据

1. **两个可运行产物**：个人安装包、服务部署包/固定镜像；分别有校验值、安装与更新说明。
2. **共同业务与技能契约**：同一完整工作包覆盖目标、材料、事实、研究、草稿、审核、任务/期限、客户沟通与交付；不因存储差异削弱权限或财务规则。
3. **个人独立与资源**：干净目标机无开发工具；无团队服务也能使用核心流程；完整进程资源、重启/休眠、升级及卸载保留数据有记录。
4. **部署与协作**：持久卷、配置、健康检查、数据库迁移、唯一调度入口、角色/并发/撤权和恢复有记录。
5. **RAG 实际可用**：资料版本、实际覆盖、反证、撤回和引用核对；模型配置与离线范围明确。
6. **数据可迁移和恢复**：个人工作区备份/恢复；迁入部署版时核对身份、权限、业务及文件版本。不共享数据库目录，不承诺双向离线同步。
7. **状态真实**：性能门槛未过或缺少一种产物时保留 prerelease 状态，不用源码包、远程快捷方式或开发运行器充数。
