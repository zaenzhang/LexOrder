# LexOrder｜程序总览 → 当前程序任务工作区

本轮只更新隔离 HTML 交互预览，不修改正式业务页、共享应用壳、schema、API 或迁移文档。

## 1. 交互结构

采用两层页面：

1. **程序总览**：当前案件下所有程序的统一列表。每行展示程序名称、程序类型、受托／关联性质、审理机构、案号、程序状态、实际受理日期、实际终结日期、环节数、庭期数、期限数、待办数和任务汇总。右上提供「新建程序」；另有「全案任务」入口。
2. **程序任务工作区**：点击某个程序后进入该程序的任务界面。主区域展示该程序真实环节任务，支持环节筛选、Board／Table、待办／已办结／已取消；右侧展示程序信息、庭期和法律期限。页面可独立定位，保留程序 ID 和筛选上下文。

不再在程序详情里并排放一个程序序列导航。程序总览负责回答“本案有哪些程序、每个程序是什么状态”；进入某程序后，任务界面只处理当前程序。

## 2. 入口与路由

- 左侧「程序」仍是唯一案内入口。
- 程序总览：`/matters/{matterId}/tasks?view=procedures`
- 当前程序工作区：`/matters/{matterId}/tasks?view=tasks&procedure={procedureId}&scope=procedure&scopeId={procedureId}`
- 新建程序：沿用 `newProcedure=1` 页面状态；从程序总览右上「新建程序」进入。
- 新建任务：从当前程序工作区进入独立表单页，默认要求选择当前程序内真实环节。
- 全案任务：从程序总览「全案任务」进入，保留事项级任务；事项级任务不被误显示为某个程序的任务。
- 从任务详情返回时恢复原程序；路由解析保留 `procedure`、`scopeId`、`stageScope`，刷新重建会回到同一程序及环节筛选。

## 3. 对象与业务边界

- `Procedure` 是法院／仲裁或其他机构的程序记录。
- `Task` 通过真实 `stageId` 关联到程序环节；当前数据模型没有独立的程序级任务外键。
- 因此，程序工作区只显示该程序各环节的任务。没有环节的事项级任务由「全案任务」入口访问，不会因同一案件或同一天被自动挂到某个程序。
- 庭期与法律期限仍然是独立记录，分别显示在当前程序工作区的右栏。
- 任务安排、办结、取消和重开不改变程序状态、庭期或法律期限。
- 已终结程序保留历史，只读展示，不开放未来任务和未来日程写入。
- 多个程序同时显示，不根据列表顺序推断程序之间存在法律前置关系。

## 4. 本轮实际交互验证

在 Chromium 中以隔离页面内容执行 DOM 点击、选择、输入和表单提交：

| 验证项 | 结果 |
|---|---|
| 初始进入程序总览 | 显示 3 条程序记录 |
| 新建程序入口 | 总览页右上始终可见 |
| 点击一审「进入办理」 | 进入一审任务工作区 |
| 一审任务 | 显示 3 项环节任务 |
| 一审庭期／期限 | 分别显示 1 条庭期、2 条期限 |
| 环节筛选 | 选择「开庭准备」后只显示 1 项任务 |
| 点击任务卡片 | 进入独立任务详情 |
| 返回 | 恢复一审任务工作区 |
| 路由恢复 | 手动重新执行 `parseHash()` + `render()` 后恢复一审工作区 |
| 从当前程序新建任务 | 表单固定为程序环节任务，环节选项属于当前程序 |
| 保存新任务 | 返回同一程序工作区，新任务可见 |
| 当前程序新增手工期限 | 保存后返回原程序工作区，期限数从 2 增至 3 |
| 当前程序登记庭期 | 保存后返回原程序工作区，庭期数从 1 增至 2 |
| 新建程序 | 提交后总览由 3 条增至 4 条，新程序可见 |
| 事项级任务 | 通过「全案任务」入口查看，不混入程序任务 |
| JavaScript | `node --check` 通过；Chromium 页面无 JS／console 错误 |

## 5. 验收限制

浏览器对本地文件和 localhost 导航返回 `ERR_BLOCKED_BY_ADMINISTRATOR`。因此，本轮通过 Chromium `set_content` 加载同一 HTML，完成了真实 DOM 交互测试；没有完成从磁盘 URL 打开、浏览器硬刷新和 Tauri WebView 验收。路由恢复通过重新解析当前 hash 并重新渲染验证，不将其描述为真实浏览器硬刷新。

## 7. 页面顶部精简（本轮补充）

按用户反馈再次删除业务内容区多余的标题带和装饰性分隔线：

- 程序总览不再显示单独的「程序」大标题；程序数量、事项级任务提示和「全案任务／新建程序」放在同一行工具栏。
- 程序工作区不再显示独立的大号「一审」页面标题。当前程序身份与状态放在紧凑摘要行；「一审 · 律师准备任务」作为实际内容区标题。
- 移除程序总览工具栏下方的分隔线。
- 移除程序任务筛选工具栏上方的分隔线。
- 不使用缩小字号代替信息层次；程序名称、程序状态、任务区标题和数据计数仍按正常正文层级呈现。

- 程序总览 `h1` 数量为 0，工具栏 `border-bottom-width=0`。
