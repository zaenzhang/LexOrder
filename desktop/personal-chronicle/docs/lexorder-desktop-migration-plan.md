# LexOrder 网页版到个人桌面的迁移工作计划

以原 [产品需求](../../../docs/PRODUCT_REQUIREMENTS_ACCEPTANCE.md) 和 [实施编号](../../../docs/WORKBENCH_PLAN.md) 为追踪入口。本机总清单位于 LexOrder 研究归档。本计划负责网页操作到个人桌面的映射及验收。业务状态和实现进度以主计划为准。

## 1. 目标结构

每个案子对应一个工作空间。顶部选案只替换 `matterId` 上下文，左侧沿用 Chronicle 固定菜单树。Workspace 使用「材料」「事实与研究」「程序与任务」「文书与交付」「办理记录」「财务与用印」。两个分组内部仍可进入独立页面和深链接。案件概览从左上首次选案和案件总览进入。我的工作台、案件总览、客户与收案、日程、审批及跨案财务是跨案入口。Chronicle 示例保留原菜单位置和行为。

每案在用户选定的根目录下绑定一个实际目录。可使用「案号 · 案名」作为初次建议目录名，应用内身份始终用已有 `Matter.id`。读取关系支持原 `DocumentFolder`、程序、任务、证据及引用；同一已入卷文件可在多处引用，绑定一份版本。

| 区域 | 内容与处理 |
| --- | --- |
| 收件 | 用户明确导入、拖入或选择扫描来源。监听发现文件提供待归卷建议，登记前确认归属。对未完成拷贝、临时文件、重名和忽略规则给出明确表现。 |
| 工作稿 | 原 Launcher 签出记录绑定案件、材料版本族和基线。默认编辑器修改工作副本；原有快照、幂等键、基线、回执及冲突保稿机制负责写回。团队掉线时先保稿，恢复连接后重新校验权限和基线。 |
| 已入卷版本 | 由现有存储服务管理原件，数据库保留版本族、版本、哈希和引用锚点。界面按卷宗分组展示；用户移动或重命名工作目录时，通过显式重新定位改变映射。历史引用继续使用已登记的精确版本。 |
| 交付与导出 | 生成的工作文件可保存在案目录。正式交付记录固定已登记材料版本、对象、时间和凭据。归档导出和个人备份各有独立入口与回执。 |
| 云同步与外部工具 | 云盘可承载用户选择的工作文件交换目录。本地嵌入式数据库保持应用单写。Codex、WorkBuddy 与第三方 MCP 通过已授权的同案资源和工具查询；写回使用候选记录，只在业务服务接受后成为当前修订。 |

目录绑定先核对 canonical 路径与所属案件。相同目录重复绑定、目录改名、断开云盘、外部删除和同名文件纳入验收。跨案共享由数据库关联表达。审批材料、律师决定和财务流水继续使用现有业务对象。

## 2. 逐流程清点与迁移处分

逐项登记原网页入口、操作、服务、输入、校验、读写对象、成功状态、失败恢复、目标入口与验收证据。一个原操作只设一个服务归属；工作台、案件页和全局汇总可共享深链接。可选处分为直接复用、桌面改编、并入同一入口、仅在线团队、暂缓。确认与完成分开登记。所有原流程必须有一项处分，所有桌面写入必须能回查原服务与编号。

### 网页审查结果

已拉起原 LexOrder 网页界面并使用隔离个人会话。检查案内八个顶层分区和全局 24 个入口，结合原服务代码登记动作。原收案入口转到案件列表的「收案」页签，原用印入口回到审批中的用印类别。桌面沿这些已存在的归属聚合操作。个人样本中无客户、财务等业务记录的页面仅验证入口及空状态，历史样本的真实写入和团队角色分支按批次补验。

## 3. 权限精简

- 个人版可将成员邀请、跨角色派单、团队角色配置和多人会签等界面归在线团队。已确认等价的个人动作，可由当前本人直接确认，记录原业务状态、操作者和审计。要先从同一个服务验证等价性。
- 保留工作区隔离、案卷归属、读写分离、版本精确性、归档锁、财务/交付完整性、MCP 授权与撤回。前端按能力展示，实际写入时还由服务复验。关联客户、材料或任务时校验同案或已授权关系。
- 权限审查逐个区分入口可见、可读对象、可执行动作、审批条件。若某权限只有团队组织意义，登记剥离后的入口和业务后果，再移出个人界面。原在线版规则继续由在线服务管理。

## 5. 执行与退出标准

1. 每批先在网页版带样本浏览并复核原动作，核对总清单适用条目。标记无样本、有空状态、已有读取、已有写入、拒绝路径、尚未迁移。只登记实际执行的结果。
2. 先迁一条对应入口的完整读写，再复用到相邻页面。每新增集合先分页或按案拉取；监听按明确的工作稿绑定注册；复用既有幂等与版本规则，避免重复扫描、全量搬运和重复哈希。
3. 对照源表与目标记录两次核对。发现总清单漏项、冲突或表述不符时，回填原编号和归属。当前新增「案件目录映射」「跨案恢复验收」「外链与内嵌 PDF 并测」「精确版本 Sheet」已在本计划登记。
4. 每批验收实际服务上的成功、空状态、校验拒绝、失权、并发或断网恢复。导航/样式遵守 [Chronicle 与 Base UI 约束](../AGENTS.md)，检查动画、键盘、窄窗口、缩放、滚动和默认编辑器。所有冒烟问题写回 [迁移记录](lexorder-personal-migration.md)。
5. 只有原流程逐项完成、并入可追、或明确归属在线/延期后，才关闭该批。本轮计划已建立。桌面首片、网页版入口审查和已实现范围见迁移记录，整项目尚在迁移。

### 原网页路由核对

以根项目 `src/app` 下 43 个 `page.tsx` 为入口，追到页面引用的组件、写入动作及守卫。下表同一行的原路由共享一项归属。案内八个顶层分区的组件与操作详见[案件工作区逐项对照](lexorder-matter-ui-audit.md)。源码审查覆盖路由全集。运行记录使用隔离个人工作区，团队和管理界面按职责审查代码。

| 原路由 | 在 Tauri 个人版的归属与范围 |
| --- | --- |
| `/`、`/schedule`、`/notifications` | 律师工作台的今日事务、上海时区月日程、业务通知与已读。原 Chronicle 示例工作台、日历与通知仍可单独访问。 |
| `/matters`、`/matters/[id]` | 案件总览与独立案卷。可编辑基本资料、程序、庭期、任务、目标/指示及其修订，办理记录、证据核对、材料、文书、财务和交付均使用当前案件身份。 |
| `/clients`、`/clients/[id]`、`/clients/follow-ups`、`/contacts` | 客户查找、新增、案卷关系、联系人与跟进，外部通讯录查找和新增。复杂客户合并需保留来源及撤销历史，单列后续。 |
| `/intakes`、`/intakes/[id]`、`/conflicts` | 收案关联客户、诉讼地位与对方、预检/正式冲突检索、人工结论、补正名称和案情、撤回重提、本人确认转案。全字段补正表、旧轮次材料对比仍在原系统。 |
| `/inbox`、`/express`、`/preservation` | 办案事务按案处理法院来件去重、判断归属及附件；快递收寄，保全对象、财产及续期。承运商联网订阅取决于服务配置。 |
| `/finance`、`/finance/reconciliation` | 案内和全局财务共用账簿。到账、支出、本人确认或拒绝、合同及分期、收款与应收核销、已开发票的票款匹配。多人审批按在线工作区角色运行。 |
| `/approvals`、`/approvals/seals`、`/seals` | 把个人应作的决定放在收案、财务和案内用印。申请、批准/驳回、撤回与实盖材料分别留痕；仍核验法人章、执行人和本案权限。多人审批中心归在线团队。 |
| `/archive` | 办案事务可做收尾、查缺项、绑定制度、逐项核验、退回重送、本人手动批准和 ZIP 导出。已结案或中止的案件按原权限重开；正式归档后保留锁卷，补充归档另建核验快照。 |
| `/reports`、`/firm-resources`、`/policy` | 业务统计与 Excel 导出；资料分类、上传、替代、历史版本及精确下载，个人可查制度资料。统一制度发布归在线管理。 |
| `/announcements` | 全所公告及发布归在线团队。个人业务提醒进入「业务通知」。 |
| `/settings`、`/settings/profile`、`/admin/firm-profile` | 本机执业资料有姓名、联系方式和并发修改检查，机构档案与全所流程开关归在线。 |
| `/admin/document-templates`、`/admin/templates` | 文书模板可上传、启停并按案填充出稿。流程/环节模板沿用已有数据，配置台和批量更新另验。 |
| `/admin/audit`、`/admin/archive-policy` | 个人可查近 30 天操作记录，并为工作区归档指定已上传的制度原文、版本及生效日期。组织级归档策略设置归在线管理。 |
| `/admin/ai`、`/admin/reminders`、`/admin/express` | 外部服务密钥、Webhook、企业邮箱和服务商管理维持在线职责。个案自动解析、规则提醒及第三方个人授权另按 RQ06/18/20 验收。 |
| `/admin/import`、`/admin/custom-fields` | 个人通过材料、来件、资料和模板的相应入口导入。旧系统整库导入、自定义字段设计与迁移需另做数据兼容验证。 |
| `/admin`、`/admin/users`、`/admin/roles`、`/admin/teams`、`/admin/approval-permissions`、`/login` | 组织用户、权限、团队和登录维持在线工作区。个人运行时用私有工作区身份、受限回环通道和原服务的读写检查。 |

### 后续验收边界

应优先补验卷宗排序与批量分类、完整事实冲突与时间精度、文书复核流、复杂任务依赖及跨版本影响。连接器、向量检索、OCR 和外部通知需各自的授权和配置。台账与界面已接的操作以[隔离验收脚本](../../../tools/workbench-m1/chronicle-smoke/README.md)和[迁移记录](lexorder-personal-migration.md)为准。
