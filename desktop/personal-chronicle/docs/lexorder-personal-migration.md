# LexOrder 个人版｜Chronicle 案件迁移

Chronicle v3 是个人版新基线。按网页原流程逐项迁移、文件夹设计与权限处置见 [详细迁移工作计划](lexorder-desktop-migration-plan.md)。案内分区沿用模板的内容区、主题变量、字号、间距和菜单。桌面用单个 Tauri WebView。Chronicle 开发服务器只监听回环地址，访问隔离的 LexOrder 个人运行时。

## Base UI 组件选择

界面、导航与动画变更遵守 [个人版界面约束](../AGENTS.md)。

官方 Quick start 提供组件结构和行为，项目沿用 Chronicle 仓库已经封装的 Base UI 与 shadcn 组件。用 `render` 把按钮样式附在链接上时设置 `nativeButton={false}`。不同业务 URL 由链接和 `aria-current` 表达，同一页面的选择和弹窗由 Base UI 组件负责。

| 位置 | 选用实现 | 业务判断 |
| --- | --- | --- |
| 左上工作空间 | Chronicle 侧栏控件与 Base UI DropdownMenu | 打开时读授权案件第一页。完整列表与搜索从「案件总览」进入。 |
| 案件列表 | Chronicle `DataTable`、Input、Button | 搜索与分页调用现有案件服务。行内链接支持键盘进入案卷。 |
| 案内分区 | Chronicle `NavMain`、PageHeader、Card 与 Badge | 六个主入口在「本案」内，跨案入口在「工作区」内。「案件」打开案件列表，客户与收案在客户页使用小 Tabs 切换。当前 URL 决定工作空间及高亮分区。 |
| 原文出处 | Chronicle Card、Button 和现有同源 PDF 预览 | 固定键包含要点 ID、修订号及出处 ID，重新打开先经过原服务校验。 |
| 人工核对 | Chronicle AlertDialog | 明示本版修订，调用 `confirmEvidenceItem`，保留原并发检查及审计。 |
| 办理记录 | Chronicle NativeSelect、Textarea、Button | 调用原记录的新增和修改动作，保留事务审计和并发检查。 |

## 案件工作空间与总览

- 左上切案菜单的「＋ 添加工作区」直接打开新建收案表单。填写后沿用收案核查与本人确认流程，转为案件时进入新案概览。表单中的「返回列表」回到收案目录。
- **添加工作区冒烟。** Windows Chrome 在隔离个人工作区验证了加号的位置与键盘进入、缺少必填项时拦截提交、取消后重开、保存收案及核查后转案。新案出现在切案名单。首次冒烟发现「返回列表」被识别为按钮，且「保存收案」「登记核查结论」未触发表单提交。恢复导航链接语义并显式设置提交按钮后复验通过。

- 左上律迹字标下方的切案按钮单行显示案名和展开箭头。侧栏收起时保留箭头与切案操作。案内分区的面包屑以案名链接至该案概览。同一窗口内，选择已访问案件回到该案最近一次访问的分区，初次进入打开概览。直达案页以 URL 确定案卷与分区。「本案」一级名称是概览、程序、材料、争点、文书、案务。概览和程序可直接进入，其余四项复用 Chronicle 的整行展开控件。「本案」和「工作区」沿用 Chronicle 的 12 px 中等字重与次要文字色。标题行高 24 px，用分组间距区分。子页使用同一二级列表、缩进线和选中态。文书与交付页面从「文书列表」进入。侧栏图标按用途选择 Lucide 线形图标，选中项使用主题主色。个人版恢复模板的 16rem 宽度和 Inset 侧栏，通知与设置仍固定在底部。
- **侧栏冒烟。** 原个人版侧栏宽 13.5rem，部分父项需单击独立箭头折叠，且父项和首个子页会同时高亮。Windows Chrome 对照「Auth pages」确认两边使用相同的字号、行高、圆角、图标位置与子项缩进。复查 1464 px 双层展开、浏览器前进后退、图标模式选中，1000 px 高度受限时的独立滚动，以及 390 px 抽屉导航后关闭。首次脚本把存在型 data-active 属性按字符串 true 比对，改用属性存在性后通过。

- **侧栏和客户页签复验。** 在 Vite 预览验证「本案」「工作区」的紧凑标题、六个一级短名称、选中图标的主题色，以及「聿」图标在字标右侧对齐。从侧栏进入客户，核对客户、收案、外部联系人三张表及冲突预检。浏览器返回恢复相应页签，方向键和空格可切换，空名称不能提交。组件测试核对冲突命中、无命中、读取失败和其他工作区路径匹配。首次冒烟中概览和程序仍显示原名称，补齐这两个一级入口的短标题后通过复验。
- 「工作区」使用案件、今日、客户、日程、财务和工具作为侧栏名称。「工具」包含技能、文书模板、资料库和业务报表，子页继续高亮同一侧栏入口。客户使用一个侧栏入口。页内沿用 Chronicle Users 的页签、筛选工具栏与表格布局，依次显示客户列表、收案、外部联系人和冲突预检。原有直达路径决定选中的页签。冲突预检提交后以表格显示命中提示。通知与设置复用 Chronicle 侧栏底部的导航按钮、图标和快捷键，分别进入个人工作台的通知和设置。跨案事务从今日办理进入。
- 工作台页面主标题直接复用 Chronicle 的 `PageHeader`。标题沿用 `font-heading text-2xl font-semibold tracking-tight`，说明文字为 `text-sm text-muted-foreground`。今日办理、法院来件和案件概览沿用模板的操作区对齐。
- **标题验收发现 · 已修复。** Vite 直接打开法院来件、办案事务和归档入口时，三个入口残留 Next.js 异步页面写法，React Router 报错。入口统一从 React Router 读取查询参数，保留来件返回来源、事务分区和指定案件归档。
- Chronicle 示范页从「设计参考」打开，保有原模板导航、Production／Staging 和示例数据。个人办案壳将「律迹」字标放在案件选择器上方。切到个人工作区时，「本案」分组保留并禁用。打开具体案卷后恢复交互，切回案件可恢复上次使用的页面。底部复用模板的通知、设置与账号行，账号菜单使用本机业务入口。长侧栏和正文可分别滚动。
- 设置正文复用 Chronicle 的响应式分组菜单、资料摘要和设置卡片。设置分区与主侧栏共用滑动选中指示，保留各自的颜色和二级缩进。同一级、同一组内垂直滑动，跨层或跨二级分组时直接定位。父级展开时使用较浅底色。启用系统减少动态效果的偏好时取消过渡。菜单包括执业资料、外观、应用 AI、操作记录。资料、AI 和审计沿用个人运行时接口。外观复用现有主题偏好，提供系统宋体选项。通知正文复用 Chronicle 收件箱，按北京时间分组，支持查看全部、筛选未读、单条及全部标为已读。通知列表与顶栏铃铛共享查询和已读刷新。
- 切案、访问参考页面和返回案件总览时维持同一侧栏。最近案内分区和固定出处保存在当前窗口会话，刷新整页或重启会重置这部分状态。双案切换已用隔离运行时验收。多案并排窗口仍待验证。

## tauri-ui 桌面工具

- 开发构建按 Ctrl+D 或 Cmd+D 切换调试面板。用 Chronicle Card 和 Base UI Tabs 显示环境、已脱敏的路由、尺寸、像素比、缩放、正文及侧栏滚动与错误计数。Chrome / Edge 的 DOM 检查使用原开发者工具。调试浮层打开时外部正文仍可操作。
- 桌面外链处理复用 Tauri opener。受信的当前应用来源在 WebView 内导航。外部 HTTP(S) 顶层导航或新窗口请求由系统默认浏览器打开；其他协议和非本应用回环地址拒绝。PDF 在材料页 Sheet 或争点出处栏内预览。
- Windows 实测 Ctrl+D 打开，Ctrl+- 后页面 1372 × 858 → 1524 × 954，设备像素比约 1.575 → 1.4175。正文偏移由 251 → 957 px。模板署名外链进入 Edge，桌面原页面保持。材料页 PDF 阅读器在本窗口加载完成。
- 首次实测发现 Tauri 默认禁用窗口缩放快捷键，调试构建显式启用 Ctrl+-／Ctrl+0。PDF 抽屉首版焦点被内嵌阅读器接收，现将初始焦点放在关闭按钮上。文件导入使用原资料摄入服务和同一请求标识，支持失败时留在表单继续处理。

## 三端桌面宿主与材料拖放 · 2026-11-20

**已确定的范围。** 在 Lexorder 仓库继续建设桌面宿主。以 Windows、macOS、Linux 跑通同一办案流程为验收范围，可复用方案成熟后评估独立框架。

### 桌面架构

    Tauri 2 / Rust
      系统 WebView、目录选择、插件清单权限、Sidecar 启停
          ↓ 仅打开已就绪的回环地址
    一个现有业务 HTTP 服务 / Bun + Next.js standalone
      ├─ Chronicle / Vite + React Router 静态文件
      ├─ 现有案件 API → Prisma → PGlite
      └─ 固定版本材料和私有工作区文件

`bun run build:desktop` 构建 Chronicle 的静态资源并装入已有 standalone 的 `public/_chronicle`。直接访问案卷深链接时，现有服务返回缓存于进程内的 SPA 首页。资源和业务 API 共用同一个 HTTP 地址，原 Chronicle Next.js 应用、代理和独立监听端口已经从桌面启动链删除。界面路由按需装载，固定材料和上传走原业务端点。发布版资源由 Tauri 打包，团队版继续用现有服务端应用。

Tauri 使用官方 Shell 和按系统生成的 `externalBin` 随程序启动 Bun 1.4.5。业务先完成工作区锁、PGlite、鉴权健康请求和静态首页检查，宿主随后创建主 WebView。关闭窗口时宿主通知 Bun，循环等待业务子进程、数据库和锁清理。进程被关闭时控制管道 EOF 能触发清理。Linux 和 macOS 使用系统 flock，Windows 的独占标记在 Bun 本身被强杀时保持封闭保护。会话以 HttpOnly Cookie 连接，业务拒绝和会话失效由响应标记区分。Windows 使用 WebView2，macOS 使用 WKWebView，Linux 使用 WebKitGTK。[Tauri 官方 Sidecar](https://v2.tauri.app/develop/sidecar/) · [React Router](https://reactrouter.com/start/declarative/routing)

### 插件清单 v1

将 JSON 放在应用本地数据目录的 `plugins/<id>/manifest.json`。目录和清单 ID 必须一致。版本 1 的案卷命令在当前案卷的命令面板出现，由宿主导航到该案卷的已有分区。在「查看本机插件」中可看到加载结果和无效清单。例子如下。

```json
{
  "apiVersion": 1,
  "id": "case.review",
  "name": "归档复核",
  "commands": [
    { "id": "open-materials", "title": "打开复核材料", "section": "materials" }
  ]
}
```

宿主只允许已就绪的主 WebView 读取清单。清单无法提供可执行代码、任意路径或任意 URL。材料和其他业务记录继续使用现有权限。自绘插件、第三方执行隔离、扩展审批和发布渠道属于后续 API 版本。
